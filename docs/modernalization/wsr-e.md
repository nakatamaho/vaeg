# WSR-E：初期化経路・アドレス選択・実機検査の調査記録

## 1. この文書の位置付け

M143のW1段階で行った、WSR-EのI/O検出と初期化手順の調査をまとめる。
対象はPC-88VA上でのボード検出であり、描画、VRAM転送、BLT、性能測定の
実装仕様を確定する文書ではない。**G143はNOT_READYである。**

重要な結論は次の三点である。

1. 実機では、現在のプローブによる初期化なしの全候補検査と、設定7への
   暫定初期化付き検査のいずれでも、期待するSR06応答を得られていない。
2. 調査したDOS用ドライバには、VGA側の初期化に入る前にボード制御ポートへ
   7Ahを書いて読み戻す検出経路がある。現在のプローブはこれを行わない。
3. WSR-Eに割り当てられたWindows用ドライバには、現在のプローブにない
   **43E0h＋アドレスオフセットへの01hの二重書き込み**がある。
   同ドライバはmiscにE3hを使うため、別のDOSドライバが使うEFhとの違いだけで
   E3hを誤りとは判定できない。

これらは、現在のプローブが参照ドライバの処理を完全には再現していない
という具体的な相違である。しかし、**どの相違がVA実機での無応答の原因かは
まだ実証していない**。ロータリー位置、接触不良、ボード故障の確定にもならない。

文書は依頼された`docs/modernalization/wsr-e.md`に置く。
既存の計画書は別の綴りのディレクトリにある
[WSR-E計画](../modernization/wsr-e-pseudo-sprite-plan.md)を参照する。

## 2. 証拠の区分と調査対象

以下を混同しない。

| 区分 | 今回確認したこと | その証拠だけでは確認できないこと |
|---|---|---|
| ボード写真・付属設定表 | チップ表記、候補アドレス表 | 現在のロータリー位置、電気的な動作状態 |
| 実機プローブ | 実際に読めた値、処理の到達点 | 未実行の初期化手順の有効性、FFの電気的原因 |
| ドライバ文書・INF | 対応宣言、WSR-Eに割り当てるモジュール | VAでの動作保証、各処理が必ず必要という保証 |
| 静的コード解析 | 条件分岐、I/O命令の幅・順序、ポート表の参照 | ハードウェアが書き込みを受理すること |
| 隔離した命令実行 | 合成I/O条件下での経路・I/O列の再現 | 実機の有効化、Windows全体の動作、リレーの安全性 |
| vaeg上のDOS実行 | プローブの実行・ログ・終了コード | 実物の初期化仕様が正しいこと |

私有入力の識別には次の中立的な名称を使う。

- **DOS参照D1**：対応文書にWSR-E/Gを挙げる、CL-GD54xx系のDOS用表示ドライバ。
- **Windows参照W1**：WSR-Eの表示デバイスに対するINF割り当てを確認できる
  Windows 95用パッケージ。その16ビット表示ドライバとE-bank用mini-VDDを解析した。

原本のファイル名・絶対パス・ハッシュ、原文、逆アセンブル、コード内アドレス、
未加工の写真・ログ・トレースはGit外に保持する。この文書の処理図・表は独立に
記述した動作の要約であり、原文や逆アセンブルの転載ではない。
インストーラやドライバ全体をホストOSまたは実機上で実行してはいない。

## 3. ボードとアドレス選択

### 3.1 確認できたチップと未確定のロータリー位置

ボード写真の主要IC表記は**CL-GD5428-80QC-A**である。
ただし、基板上の固定の三角印や数字0を、そのままロータリーの選択位置と
解釈してはならない。以前の「設定0」という写真の読み方は撤回している。
設定7の可能性はあるが、現在位置は未確定のままである。

### 3.2 候補とオフセット

設定番号を`n`、ポートへの加算値を`d = 2*n`とする。
設定表とDOS参照D1の列挙処理は、次の候補について整合する。

| 設定n | オフセットd | 偶数側の下位バイト | SR index / data | ボード制御候補 |
|---:|---:|---|---|---|
| 0 | 00h | E0h | 44E0h / 45E0h | 40E1h |
| 1 | 02h | E2h | 44E2h / 45E2h | 40E3h |
| 2 | 04h | E4h | 44E4h / 45E4h | 40E5h |
| 3 | 06h | E6h | 44E6h / 45E6h | 40E7h |
| 4 | 08h | E8h | **使用禁止・検査対象外** | **書き込まない** |
| 5 | 0Ah | EAh | 44EAh / 45EAh | 40EBh |
| 6 | 0Ch | ECh | 44ECh / 45ECh | 40EDh |
| 7 | 0Eh | EEh | 44EEh / 45EEh | 40EFh |

**setupの46E8hは共通ポート**であり、設定番号のオフセットを加えない。
DOS参照D1のポート表展開でも、この共通setup値は候補別の加算対象から外れる。

### 3.3 今回の解析に関係するポート

名称は参照コードとVGAレジスタ対応に基づく整理であり、WSR-Eの未確認の
ボード制御ビットまで意味が確定したということではない。

| 設定0でのポート | 設定7 | 解析上の用途 |
|---|---|---|
| 40E1h+d | 40EFh | ボード制御・表示切替に関係するポート。D1の7Ah読み戻し検査にも使用 |
| 42E1h+d | 42EFh | 別系統の検出や、より広い表示設定処理で使うボード側ポート |
| 46E8h（固定） | 46E8h | setup。今回の各初期化列で18h、08hを書き込む |
| 42E0h+d | 42EEh | misc output書き込み |
| 43E0h+d | 43EEh | VGA側の有効化に対応するポート。W1では01hを2回書く |
| 44E0h+d / 45E0h+d | 44EEh / 45EEh | sequencer index / data。SR06検査に使用 |
| 4CE0h+d | 4CEEh | misc outputの読み取り側 |
| 4EE0h+d / 4FE0h+d | 4EEEh / 4FEEh | graphics controller index / data |
| 54E0h+d / 55E0h+d | 54EEh / 55EEh | CRTC index / data。CR27でチップ識別値を読む |
| 5AE0h+d | 5AEEh | status読み取り／書き込み側feature-control用途に対応するポート |
| 51E1h+d | 51EFh | 別系統識別のC2h比較に使うポート |
| 57E1h+d | 57EFh | 上記C2h分岐で、読み取り値のbit 7を落として書き戻すポート |

SR indexとdataのバイトアクセス先は0100h離れている。
これと、indexポートへの`OUT DX,AX`のワードアクセスは別の問題である。
後者の上位バイトの扱いを、単に「port+1へのバイトアクセス」と同一視しない。
VAスロット上のワードI/O動作は引き続き実機確認が必要である。

## 4. DOS参照D1の検出経路

### 4.1 最初に別系統の識別経路を試す

D1は単一ボード専用ではない。対象の制御ポート検査より前に、別系統の
識別ポートを使う候補列挙がある。

```text
有効な各オフセットdについて
  51E1h+dを読む
  C2hでなければ次候補へ
  C2hなら候補別ポート表を設定
    42E1h+dへ08hを書く
    識別値を再確認
    該当条件なら57E1h+dの読み取り値のbit 7を落として書き戻す
    VGA側の初期化を行う
    CR27を調べ、成功なら別系統の分類を返す
全候補が不成立なら、次のボード制御ポート検査へ
```

この経路を、以下の7Ahハンドシェイク経路と一つの必須手順に混ぜてはならない。
C2h分岐のハードウェア上の適用対象が、今回の実物WSR-Eであると確認できた
わけではない。

### 4.2 ボード制御ポートの7Ah読み戻し検査

次の候補列挙では、VGAレジスタに触る前に以下を行う。

```text
有効な各オフセットdについて
  40E1h+dへ7Ahを書く
  同じポートを読む
  7Ahでなければ次候補へ
  一致した候補についてポート表を設定し、VGA側の初期化へ進む
```

設定7なら、書き込み先と読み取り先はどちらも40EFhである。
現在のプローブはこのポートへの書き込みを禁止しているため、同じ検出経路を
再現していない。

ただし、ここで確定したのは**D1がこの操作を行うという事実**である。
「7Ahを書かないとすべてのWSR-EでVGA I/Oが無効になる」や「7Ahが純粋な
有効化だけを行う」といったビット単位の意味までは確定していない。

### 4.3 ハンドシェイク成功後の初期化とCR27

該当経路の主要なバイトI/O列は次のとおり。

| 順序 | 書き込み先 | 値 |
|---:|---|---:|
| 1 | 46E8h | 18h |
| 2 | 42E0h+d | 01h |
| 3 | 46E8h | 08h |
| 4 | 42E0h+d | EFh |
| 5 | 54E0h+d | 27h（CR27を選択） |

その後55E0h+dを読み、値をFChでマスクする。

- マスク後がFChなら、その候補を不成立として先へ進む。
- そうでなければチップ分類へ進み、再度読み取った値のFChマスクが98hなら
  特定の分類を選ぶ。それ以外には別の分類がある。
- この検出部分には、CR27より前のSR06アンロック／ロック署名検査はない。

**「CR27を先に読めること」と「SR06に期待した応答があること」は別の条件**である。
SR06だけを入口にした現在のプローブと、同じ判定方式ではない。
また、D1の比較はマスク付きなので、実機で観測したCR27の生値が98hだったと
読み替えてはならない。実物WSR-EのCR27値はまだ得られていない。

### 4.4 後続の別ボード検出と初期化

この候補列挙でも不成立なら、D1は別のポート配置のボードや内蔵アクセラレータ
の検出へ進む。より上位の初期化処理では、検出成功後にモード設定やメモリに
関係する処理を呼ぶ。

したがって、元ドライバの「検出」オプションや起動全体を、VA上の安全な
読み取り専用検査として扱ってはいけない。目的のボード以外のポートに
書き込む経路も存在する。

## 5. Windows参照W1の初期化経路

### 5.1 INFから対象を分ける

W1には表示用とサウンド用のデバイス定義がある。今回調べた表示側では、
WSR-Eに16ビット表示ドライバとE-bank用mini-VDDが割り当てられている。
サウンド用の定義・ドライバを、VGA初期化の根拠と取り違えない。

この割り当ては、一般的なCL-GD54xx用ドライバというだけでなく、WSR-Eの
表示側に使うコードを選ぶための根拠になる。ただし、INF上の対応はVA上での
動作保証ではない。

### 5.2 16ビット表示ドライバ：まずCR27、FFなら初期化

今回追跡したローカルな処理経路は次のとおり。

```text
選択済みポート表を使う
  CR27を選択して読む
  FF以外なら、この初期化ルーチンを抜ける
  FFなら
    識別ポートを調べる
    C2hの系統なら、57E1h+dのbit 7を落とす処理を行う
    共通のVGA初期化列を実行する
    呼出し元へ戻る
```

ここでの判定は**生のFFとの比較**であり、D1のFChマスクによる分類とは異なる。
「FF以外なら抜ける」は、このルーチンで追加の起動処理を省く条件であって、
ボード全体の動作確認に合格したという意味ではない。

また、これは選択済みポート表を前提とするルーチンである。
D1のような全候補列挙を、この部分が自動的に行っているとは解釈しない。

### 5.3 共通のVGA初期化列

16ビット表示ドライバとmini-VDDの両方で、次の列を確認した。
すべてここではバイト書き込みである。

| 順序 | ポート | 設定7の場合 | 値 |
|---:|---|---|---:|
| 1 | 共通setup | 46E8h | 18h |
| 2 | misc output | 42EEh | 01h |
| 3 | 共通setup | 46E8h | 08h |
| 4 | VGA側有効化ポート | **43EEh** | **01h** |
| 5 | 同じポート、連続する二度目の書き込み | **43EEh** | **01h** |
| 6 | misc output | 42EEh | E3h |
| 7 | status／feature-control側 | 5AEEh | 00h |

今回のスキャナは4・5を省略している。
二重書き込みはコード上に実在し、抽象的な「有効化」の説明から推測して
補ったものではない。一方、なぜ二度必要なのか、一度では足りないのかは未確認である。
読み戻し方法や元の状態に戻す方法も、この列だけからは確定できない。

### 5.4 mini-VDDの呼出し文脈と後続処理

mini-VDDにも、系統識別の条件分岐に続いて上記の列を行うルーチンがある。
確認した呼出し元では、その後にボード側設定、sequencer設定などのより広い
表示初期化が続く。SR06への1206hというワード出力も後続処理に見られる。
これは現在のプローブのバイト単位のSR06検査とは別のアクセス形態である。

さらに表示設定側には、ボード制御ポートへ7Ah、7Bhを使う処理がある。
値の差だけから各ビットの機能を断定したり、その一連の処理を無条件に
検出プローブへ移植したりしてはいけない。

ここで追ったのは個々のルーチンとその局所的な呼出し関係であり、Windowsの
デバイス起動から復帰・終了までの全ライフサイクルではない。特に、
「このVGA初期化ルーチン自身が40E1h+dに書かない」ことは、呼出し以前の
全経路でボード制御操作が不要であることを証明しない。

## 6. 現在のプローブとの比較

### 6.1 W1SCANのモード

[実装と使用上の注意](../../demos/wsr-e-pseudo-sprite/README.md#w1scan-rotary-address-setting-probe)
も参照する。

- 引数なし：7候補のSR dataポートを読む。indexを変更しないため、これは
  現在選択されているレジスタの生値であり、SR06を読んだとは限らない。
- `/P`：7候補でSR06を選択し、12hを書いて12h、00hを書いて0Fhという
  読み取り署名を2組要求する。起動用のsetup／misc操作はしない。
- `/W n`：指定された1候補だけで暫定初期化を行い、その後に同じSR06検査を行う。
  引数のnは検査対象であって、写真から確定したロータリー位置ではない。

### 6.2 手順ごとの差

| 項目 | 現行W1SCAN `/W n` | DOS参照D1のハンドシェイク経路 | Windows参照W1のVGA起動ルーチン |
|---|---|---|---|
| 40E1h+dへ7Ahを書いて読む | しない | VGA setupより前に行う | このルーチン内では行わない。周辺経路は別問題 |
| 共通setup 18h → misc 01h → setup 08h | 行う | 行う | 行う |
| 43E0h+dへ01hを2回 | **しない** | この検出経路では見られない | **行う** |
| 続くmisc値 | E3h | EFh | E3h |
| status側への00h | 行う | この検出経路では見られない | 行う |
| 初期化後の主な検査 | SR06の反復署名 | CR27のマスク付き分類 | このルーチンは起動処理。後続の設定・判定は別 |

**各列は異なるソフトウェア経路である。** 全部の操作を足せば正しい、という
根拠はない。特にEFhとE3hは複数の正規のソフトウェア経路に存在する差であり、
一方だけを正解として変更する根拠は得られていない。

### 6.3 復元の限界

現行W1SCANは次の限定的な後始末をする。

- 事前のSR06が12hならアンロック状態を復元し、それ以外はロック状態を残す。
- 読み取ったSR indexが解釈可能な範囲なら復元する。不明なindexは復元できない。
- `/W`の事前setup／misc読み取りがFFなら、そのFFを元の設定値として書き戻さない。
  この場合はsetupが08h、miscがE3hのまま残る可能性がある。
- status側への書き込みを含め、ボード全体の状態を完全保存・復元するものではない。

`FF_PRIOR_NOT_RESTORED`は「FFを正常な保存値とみなさず復元を省いた」という
注意表示である。`WAKE_RESTORE`行に表示するsetup／misc値も保存した事前値であり、
復元後に再測定した値ではない。

新たに43E0h+dや40E1h+dを書き込むなら、その状態管理は別途設計する必要がある。

## 7. 実機で得られた結果

### 7.1 既存の設定0プローブ

既存のW1PROBEは設定0固定であり、後の実機試験ではSR06の期待値に対してFFが
返り、NO-BOARDで終了した。これはその検出条件の不成立であり、物理的な未装着を
確定した結果ではない。検出が不成立なので、その先のCR27などの結果は得られていない。

### 7.2 アドレススキャナ

配布したCOMと、返却されたD88内のCOMはバイト単位で一致した。
機種表示はVA、ROM識別値FFFFh、表示周波数は24kHzである。

| 試験 | 観測結果 | 判定できること |
|---|---|---|
| 読み取りのみ | 7候補のSR data読み取りがFF | その時点の読み取り値のみ |
| `/P` | 7候補すべてでSR06の4回の読み取りがFF | 初期化なしでは要求した署名を得られない |
| `/W 7` | 事前setup／miscともFF、暫定初期化後のSR06も4回すべてFF | 現行の設定7向け暫定手順でも署名を得られない |

後二者の最終表示はNONE_INCONCLUSIVEである。`/W 7`については、写真で
最終表示後にDOSプロンプトへ戻ることを確認し、返却ログにも同じ結果がある。
追加ログの前半は、以前の2セッションのログと完全一致していた。
実機の終了コードを保存したファイルはないので、表示からERRORLEVELの実測値を
捏造しない。

FFは、現在の手順で期待した応答を得られなかったことを示す。
これだけでは、未有効化、異なるアドレス、アクセス方法の不一致などを分離できず、
故障や接触不良を原因と認定できない。

### 7.3 低位E8hとタイミング結果は別件

以前のW1PORTでは、VA実機のV3でも低位E8hが00hを返した。
これはM144の実測とも整合し、「V1/V2用だからV3では必ずFF」という当初の
想定を否定する。高位の拡張ポートで今回FFが返る件と混同しない。

また、以前のR0値は15kHzと24kHzの試験で異なる。表示周波数が違う結果を
ボード有無による速度差として比較しない。W1SCAN自体はR0を測定しない。

## 8. 解析方法と再現確認の範囲

### 8.1 実行形式を分けて扱う

- DOS参照D1はMZヘッダとロード部分を分け、データセグメントとポート表を
  対応付けて検出処理を読む。
- Windows参照W1の表示ドライバはNEのコードセグメントを取り出し、16ビット
  命令として読む。データセグメントをコードとして解釈しない。
- mini-VDDはLEのオブジェクト表とページマップから内容を再構成し、32ビット
  コードを読む。16ビットのポート指定やオペランド幅プレフィックスにも注意する。

ファイル全体の単純な逆アセンブルやバイト検索だけで、データ中の偶然の一致を
I/O命令と認定しない。ポート表の実値と参照命令を照合する。
NE/LEの再配置やセレクタを含む全ロード環境を再現したわけではないため、
生の逆アセンブルに現れるすべてのアドレスを、そのまま実行時アドレスと扱わない。

### 8.2 DOS検出ルーチンの隔離実行

Unicorn内で該当ルーチンだけを実行し、I/Oを合成応答へ置き換えた。

| 合成条件 | 確認した分岐 |
|---|---|
| 設定7の制御ポートが7Ahを返し、CR27が98hを返す | 該当候補の初期化列とチップ分類へ進む |
| 同じ条件から制御ポートの応答だけを無効にする | 成功経路に入らず、他候補・他系統の検出を経て失敗 |
| 同じ条件からCR27応答だけをFFにする | チップ検出が不成立となり、最終的に失敗 |

3条件とも期待した戻り値まで到達した。これは制御フローの読み取りを裏付ける
ものであり、合成したI/O応答が実機の仕様であると保証するものではない。

### 8.3 Windows起動ルーチンの隔離実行

mini-VDDの起動ルーチンだけを、設定0と設定7のポート表でそれぞれ実行した。
系統識別ポートの応答はFFに固定した。両条件で復帰し、前述の**7回のバイト出力**が
順序・ポート・値まで一致した。43E0h+dへの連続した2回の出力も含む。

これをWindows 95全体の起動成功、実機での有効化成功、または制御ポートの安全性
の検証として扱ってはいけない。

## 9. 現時点で確定していない事項と次の調査

### 9.1 未確定事項

- 実物のロータリー位置と、その位置で応答するI/Oアドレス。
- 43E0h+dの初期状態、二重書き込みの理由、読み戻しと復元の条件。
- 40E1h+dの全ビットの意味。7Ah／7Bhの差と表示切替の関係。
- VA上で制御ポートのハンドシェイクが必要か、VGA側の有効化だけで足りるか。
- CR27の実機生値とSR06の実機応答。
- バイトI/OとワードI/Oのそれぞれの動作、および上位バイトの対応。
- 初期化・終了・再起動・電源投入で保持／消失する状態。
- VRAM窓、メモリバンク、BLTなど。これらは今回の検出結果から確定しない。

### 9.2 次の検査を設計する際の順序

1. まず43E0h+dを含む最小の有効化経路を、対象設定だけで検査する案を検討する。
   SR06だけでなく、初期化前後のCR27も切り分けに使えるか確認する。
2. 新しい書き込み先と残留状態を明示する。元の値を読めない場合に、完全復元を
   装った書き戻しをしない。
3. ボード制御ポートへ7Ahを書き込む案は別の段階として扱う。
   今までの「リレー／ボード制御には書かない」という範囲を黙って変更しない。
4. 別系統の検出やWindowsの表示設定全体を取り込まず、一つずつ原因を分離する。
5. 合成モデルで成功したことを実機仕様の証明にせず、実機結果を得てから
   vaegのボードモデルに必要な変更を判断する。

これは検査設計の方針であり、実機への追加操作を直ちに指示するものではない。
上記の参照ドライバ解析の段階では、新しいプローブ、D88、エミュレータ挙動は
変更していない。続くプローブ実装は次節で区別する。W2やリリースは開始していない。

## 10. 改訂プローブW1INIT

初期化不足とバス側の無応答を切り分けるため、別プログラムW1INITを追加した。
旧W1SCANは変更せず、ログもWSRINIT.TXTに分離する。実機で正しい初期化を
確立したという扱いではなく、参照経路を分けて観察する実験である。

### 10.1 CPU条件とバス条件を分ける

DOS参照ソフト全体の説明には最低V30／80186以上、推奨80486以上という区別がある。
これはWSR-Eが個々のV30搭載機で動作保証されるという意味ではない。
調べた検出ルーチンにはV30を理由に検査をやめる分岐は見つかっていないが、
ソフト全体の全経路やボード側の信号条件を証明したわけでもない。

W1INITは`cpu 186`でアセンブルし、バイトI/Oのみを用い、CPU種別判定や
PC-98 BIOSを呼ばない。合成実行では386系命令・プレフィックスを使わないことと、
ソフトウェア割り込みがDOSのINT 21hのみであることも検査する。
ターゲットはV3のVA系であり、98VM用のプログラムを新たに作ったわけではない。
これでソフト側の命令・BIOS依存を避けても、スロットの信号・タイミング・
アクセス幅がボードの要求を満たすかは別の未確認事項として残る。

### 10.2 明示的に分けた実験経路

- 引数なし：読み取り専用。起動用の書き込みはしない。
- `/E n`：指定候補のCR27を読み、FFの場合だけWindows参照の7回のバイト出力を
  行う。その後CR27とSR06を記録する。非FFならWAKE_SKIPを記録する。
  ボード／リレー制御ポートには書かない。
- `/D n`：指定候補でDOS参照の7Ah読み戻し検査を行う。これにはボード／リレー
  制御書き込みがある。不一致なら、その候補のVGA起動やCR/SR操作に進まない。
  一致すれば起動前CR27、EFhで終わるDOS側起動列、起動後CR27、SR06の順に記録する。
- `/D ALL`：0・1・2・3・5・6・7を列挙する明示的な書き込みオプション。
  全候補ポートの排他的な使用を確認できる環境だけで使う。

両経路ともCRTC dataやVRAMを書かず、SR06の署名をCR27到達の前提にしない。
CHIP_CANDIDATEは起動後CR27のFChマスクが98hという分類であり、SR06結果は
別に読む。単なる固定応答の可能性を含め、候補の表示は完全なボード検証ではない。

### 10.3 後始末と結果解釈

/Eのenableは事前00h/01h、/Dのcontrolは事前7Ah/7Bhを解釈できる値として
書き戻す。それ以外は不明として復元を省く。setup/miscのFFも書き戻さない。
statusを書いた場合の完全復元や、SR/CRの不明なindexの復元は保証しない。
WRITEBACK_ATTEMPTEDというログは書き込みを試みたという意味であり、
復元成功の読み戻し確認ではない。別経路の比較は別の電源投入セッションに分ける。

全FFが続いても、CPUによる拒否、故障、誤設定のいずれも確定できない。
CONTROL_GATE、CR27_PRE_WAKE、CR27_POST_WAKE、SR06を分けて解析し、
未検証の操作を足し合わせた初期化を正解として採用しない。

[詳しい使用条件とビルド方法](../../demos/wsr-e-pseudo-sprite/README.md#w1init-separated-enable-and-dos-detection-experiments)
を参照。エミュレータ本体の挙動は変更しておらず、G143はNOT_READYのままである。
