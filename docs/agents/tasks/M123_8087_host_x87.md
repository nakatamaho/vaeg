# M123 — 8087 transcendentals on the host x87

Status: **complete; G123 passed on 2026-10-18; merged to `main` at [a50f1db](https://github.com/nakatamaho/vaeg/commit/a50f1db7e378621121cae79db33ee79775e3a427)**

## Request

The maintainer asked (2026-10-17) to carry out the 8087 with the host FPU
in inline assembly on x86 and x86-64 hosts (issue #43).

## Measurements before the change (Linux x86-64, `linux-ci-gcc`)

Per instruction, SoftFloat series: FPTAN 15.7 µs, FPATAN 23.8 µs, F2XM1
11.1 µs, FYL2XP1 11.8 µs; FMUL 0.03 µs, FSQRT 0.08 µs. A program running
transcendentals continuously at the real 8087's rate would spend about 30 %
of a host core on them. The series were also found inaccurate (open ledger
entry "M123 — the 8087 SoftFloat series is inaccurate in its
transcendentals").

## Work

- `cpu/upd8087/upd8087.c`: on GCC/Clang x86 and x86-64 builds, FPTAN,
  FPATAN, F2XM1, FYL2X and FYL2XP1 run on the host x87 (`fldt`, the
  instruction, `fstpt`) with the guest rounding control, 64-bit precision
  and all exceptions masked; the host environment is saved with `fnstenv`
  and restored with `fldenv`, and the host flags IE/ZE/OE/UE/PE become the
  guest's. The 8087 domain checks, stack effects and commit rules stay as
  they were; the other instructions still use SoftFloat, whose results are
  exact. MSVC and non-x86 builds keep the series.
- `upd8087_host_fpu_available/set/active`; the setting is not part of the
  machine state.
- `vaeg.cfg` `NDP8087HostFPU` (on by default), 模擬 > 詳細設定… checkbox,
  applied at once.
- `vaeg_8087_tests`: the whole battery with the series and again with the
  host path; a new test checks the five instructions against correctly
  rounded values (mpmath, 200 bits) within one ulp, PE, the restored host
  control and status words, and that the series runs when the path is off.
  Mutation-checked: no `fldenv`, path never used, FPATAN operands swapped,
  host flags dropped.

## Results

- Speed (same benchmark, including state setup): FPTAN 0.23 µs, FPATAN
  0.24, F2XM1 0.22, FYL2X 0.22, FYL2XP1 0.25 (series: 11-24 µs).
- Accuracy, 20,000 random operands per instruction against long-double
  libm: host at most 2 ulp; series up to 1.6e16 ulp.
- ctest 94/94, selftest passed.

- Media build regression at `0654953a` (clean clone): demo disks, the SGP
  boot disk, all-demos and all-demos-msdos4 identical to the committed
  images; the utility disk and both SASI images build.
- Clean-checkout MinGW build of `0654953a`: `vaeg.exe` SHA-256
  `4207187dc628d0b0219f67250611e950709c29a5658b86f01e96352542f664ff`; its
  disassembly contains the x87 transcendental instructions.

## Follow-up: SoftFloat checked against the host x87 (2026-10-17)

The maintainer asked whether SoftFloat itself is wrong and whether the
basic arithmetic could run on the host x87 too.

- SoftFloat is correct: with the right precision values it equals the host
  x87 bit for bit, value and flags, in 4,000,000 random add/sub/mul/div/sqrt
  cases over every rounding and precision control.
- vaeg passed the wrong precision values (53/64 instead of 64/80), so the
  8087's default 64-bit precision rounded to 53 bits. Fixed
  ([1376fa80](https://github.com/nakatamaho/vaeg/commit/1376fa802217a889c371c8702a5df951674de528)), ledger entry
  "M123 — 8087 arithmetic rounded to 53 bits ...".
- Speed: SoftFloat add/mul 11 ns, div/sqrt 22 ns; the host x87 needs 14 ns
  for the instruction but 124 ns with the host environment saved and
  restored, which cannot be skipped. The basic arithmetic therefore stays
  on SoftFloat. A whole emulated FMUL takes about 30 ns; the real 8087
  needs roughly 15 µs at 8 MHz.

## Follow-up: accurate series (2026-10-17)

The maintainer has no 8087, so the target is the correctly rounded value,
not the chip's last bit. The SoftFloat series used without the host x87
(macOS arm64) were made accurate
([9b74f2fa](https://github.com/nakatamaho/vaeg/commit/9b74f2fa3475788fd851351c1fcd9238d4242490)): FPATAN with a
reduction to |t| <= 1/16 and a table of atan(k/8), F2XM1 as expm1(x ln 2),
all series at 64-bit precision and round to nearest. Worst error against
libm over 20,000 operands each: FPTAN 5, FPATAN 4, F2XM1 4, FYL2X 2,
FYL2XP1 6 ulp (host x87: 0-2). Ledger: the open entry became the fixed
entry "M123 — the 8087 FPATAN and F2XM1 series were inaccurate".

## BASIC test (2026-10-17)

host x87 on and off.
