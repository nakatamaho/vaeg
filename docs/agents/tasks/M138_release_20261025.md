## Public recording configuration

The old release jobs inherited recording OFF. All three release jobs now
explicitly set recording ON, static FFmpeg ON, public-build ON, local-only
MP4 encoders OFF. Do not enable or link local encoders in CI or releases.

`build-recording-ffmpeg.sh` builds the existing pinned FFmpeg 8.1.2 release
with the existing FFV1/PCM/Matroska/file-only configuration, disables GPL,
nonfree/version3/network/autodetection, verifies the source checksum and
runs the libavcodec archive audit. This is a native Linux/macOS/MSYS2 SDK;
Windows uses a native-format prefix in its pkg-config files. No new vendor
source, archive or SDK is tracked. Each job selects this SDK's pkg-config
prefix rather than installing a broad system FFmpeg codec package.

CMake's existing configure/prebuild archive audits remain mandatory.
`stage-recording-assets.sh` repeats the archive audit and supplies the
FFmpeg LGPL license, exact unmodified source, generated target configuration,
full tracked application source and rebuilding/relinking guide in every
package. No local-codec libraries, sources or caches enter these packages.
No patent clearance or legal release approval is inferred from these checks.

Windows/macOS post-stop MP4 uses the OS APIs. Linux public recording is MKV
only, with no bundled H.264/AAC implementation. Neither the emulator's clock
model nor any guest-visible instruction semantics is changed in M138.

## Validation design

- `check-recording-release.py` is a content-only contract for the three
  explicitly named jobs and minimal SDK configuration; it is not a general
  YAML/shell parser or a replacement for binary archive audits.
- Its independent unit tests start with the passing content fixture and
  apply one mutation, checking the exact stable error code. A complete
  content integration case is retained; no protected-history or topology
  rule is introduced or bypassed.
- Register the test with CTest, including recording-OFF configurations.
- Actual minimal SDK builds/archive audits and recording-ON public-policy
  application builds are required locally before requesting hosted CI.
- Preserve command logs and generated artifacts out of tree. Reuse prior
  M135/M136 demo/media evidence only for unchanged demo/media inputs; do not
  relabel it as an M138 regeneration or new presenter/runtime result.
