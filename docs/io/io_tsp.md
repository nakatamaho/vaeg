# TSP — テキスト／スプライトプロセッサ

[I/O解析資料の索引へ](README.md)

| 項目 | 内容 |
| --- | --- |
| I/O | `0142H`、`0146H`（関連：`0143H`、`0148H`） |
| 名称 | TSPステータス／コマンド、パラメータ／結果データ |
| 対象 | PC-88VA、PC-88VA2、PC-88VA3。機種差は個別に記す |
| チップ | VAのTSP（Text/Sprite Processor）。汎用μPD72022 IDPが機能・コマンドの参考になる |
| ブロック | システムエリア1（`0100H–01FFH`） |
| 基本アクセス幅 | BYTE（8ビット） |

## 読み方と根拠

本書は、ポートごとの機能・ビット・使い方をまとめた独自の解説である。
メーカーの原本や電気的仕様書の代替ではない。汎用μPD72022とVAのカスタムLSIが
全機種で同一のシリコンであるとは断定しない。

- **【VA資料】**：既存の[公開TSP解析](../modernization/upd72022-tsp.md)に整理された
  PC-88VA用の仕様。元資料との全項目の再照合を今回行ったわけではない。
- **【汎用】**：μPD72022データブックの仕様を同解析から整理したもの。
  VAの配線・機能・アドレス変換が同じとは限らない。
- **【実装】**：現在のvaegソースを読み直して確認した動作。実機仕様の証明ではない。
- **【既存実機記録】**：先行調査で公開済みの測定・観察。今回新しい実機試験はしていない。
- **【未確定】**：資料の不足、機種差、説明の食い違いが残るもの。

既存TSP解析の「現在の実装」の節には古い記述が残っている。例えば `ACTSCR`、
`CURS`、`EMUL` は現在のソースでは処理される。本書の実装欄は、そちらの古い
対応表をそのまま転記せず、`io/tsp.c` の分岐と受信バイト数を基準にした。

## 機能

| I/Oアドレス | 幅 | R/W | 内容 | 根拠・注意 |
| --- | --- | --- | --- | --- |
| `0142H` | BYTE | R | TSPステータス | 【VA資料】【実装】 |
| `0142H` | BYTE | W | TSPコマンド | 【VA資料】【実装】 |
| `0146H` | BYTE | W | パラメータ、連続書込みデータ | 【VA資料】【実装】 |
| `0146H` | BYTE | R | 結果、連続読出しデータ | 【VA資料】【汎用】。vaegではTSPの読出しハンドラ未登録 |
| `0143H` | BYTE | R | 本書では実機での機能を未確定とする | 【実装】常に `FFH` を返すスタブ |
| `0148H` | BYTE | R/W | TSP出力に関連するテキスト制御 | TSPコマンドではなくVA側の制御。後述 |

TSPはテキスト、カーソル、スプライト、CRT走査の制御を担当する。
GVRAMのG0/G1画面は別のグラフィックス回路が生成し、VA側の表示合成回路で
TSP出力と合わせる。TSPコマンドだけでGVRAMの解像度・ピッチ・色数を設定する
わけではない。

## 0142H, Read：ステータス

【VA資料】各ビットは次の意味を持つ。

| bit | マスク | 名称 | 1の意味 | 補足 |
| ---: | --- | --- | --- | --- |
| 7 | `80H` | LP | ライトペン位置を取り込み済み | VA資料ではライトペン使用不可 |
| 6 | `40H` | VB | 垂直帰線期間中 | システムポートのVRTC表示とは分けて扱う |
| 5 | `20H` | SC | スプライトオーバーまたは衝突あり | 詳細は `SPROV` で取得する |
| 4 | `10H` | ER | エラー発生 | コマンド、パラメータ、入力順序などの異常 |
| 3 | `08H` | EMEN | μPD3301互換の属性展開中 | VA拡張。汎用μPD72022では予約ビット |
| 2 | `04H` | BUSY | コマンド処理中 | 入力バッファ満杯とは別の状態 |
| 1 | `02H` | OBF | 出力データバッファに未読データあり | 結果を読む準備ができている |
| 0 | `01H` | IBF | 入力データバッファに未処理データあり | 次の入力を送る前に0を待つ |

### 解説

- `BUSY=0` だけでは、次の入力を書けることを保証しない。`IBF` も確認する。
- `IBF=0` だけでは、新しいコマンドが開始できることを保証しない。
- 結果読出しは `OBF=1` を待って `0146H` から行う。汎用仕様では読出しにより
  その出力バイトを消費してOBFをクリアする。
- 【汎用】エラー時は `EXIT` でコマンド待ち状態へ復帰する。
  VAの全エラー条件・タイミングを本書で実機確認したわけではない。
- 【VA資料】SCは垂直帰線時に更新され、`SPROV` による取得でクリアされる。
  OBFやSCを、単なる読み捨てのステータスビットと考えてはいけない。

### vaegでの読出し

【実装】`tsp_i142()` は保存された `tsp.status` に、動的なVBをORして返す。
通常のコマンド処理が生成する状態は主にBUSYとVBであり、IBF、OBF、ER、EMEN、
SC、LPのハードウェア動作を完全には再現しない。

| 保存BUSY | 動的VB | ほかの保存ビットが0のときの値 |
| ---: | ---: | --- |
| 0 | 0 | `00H` |
| 1 | 0 | `04H` |
| 0 | 1 | `40H` |
| 1 | 1 | `44H` |

M69で保存ステータスを消してしまう式の優先順位の不具合は修正済み。
[修正記録](../modernization/bug-fixes.md#idptsp-0142h-status-reads-erased-stored-status-flags)と
[登録I/O経路の検証](../agents/reports/m69_upd9002_idp_0142_status_composition.md)を参照。
保存ビットを正しく返すことと、各ビットの発生条件を実装していることは別である。

【実装】WORDの `IN 0142H` は下位バイトを `0142H`、上位バイトを `0143H` から
合成する。したがって上記例は `FF00H`、`FF04H`、`FF40H`、`FF44H` になる。
これは16ビット幅のTSPステータスが存在するという意味ではない。

## 0142H, Write：コマンド

8ビットのコマンドコードを送る。固定長パラメータを持つコマンドでは、続けて
必要なバイト数を `0146H` へ順に送る。16ビットのフィールドも1バイトずつ
送るものであり、`OUT DX,AX` をコマンド＋パラメータの一括送信に使わない。

### 送信・受信手順

[既存の走査試験プログラム](../../tools/pc88va/vtiming/v480pat.asm)の
`setcmd` / `setprm` は、次のように待ち条件を分けている。

| 操作 | 待つ条件 | 判定 |
| --- | --- | --- |
| 通常の新規コマンド送信 | BUSY=0かつIBF=0 | `(status & 05H) == 0` |
| 受信中コマンドの各パラメータ送信 | IBF=0 | `(status & 01H) == 0` |
| 結果データの読出し | OBF=1 | `(status & 02H) != 0` |

**各パラメータの前にBUSY=0まで待つ、と一律に書いてはいけない。**
【実装】vaegは固定長コマンドの受付時にBUSYを立て、最後のパラメータを
受け取るまで保持する。その途中で `05H` を待つと、パラメータを送れずに停止する。
既存の再構成仕様には「各パラメータも05Hで待つ」という記述があるが、上記の
ソースおよび受信状態と整合しない。本書ではこの区別を明記する。

すべての待ちに上限を設ける。特に、未実装の結果コマンドに対してOBFを
無期限に待たない。エラー回復やストリーム終了の `EXIT` は通常の新規コマンド
とは扱いが異なり、BUSY待ちで回復不能にならないよう対象仕様を確認する。

以下は送信側の説明用擬似コードであり、実機で新規に検証したドライバではない。
`wait_until` は有限時間で失敗を返し、呼出し側は各失敗を処理するものとする。

```text
send_command(code):
    if not wait_until((in8(0142H) & 05H) == 0): return timeout
    out8(0142H, code)
    return success

send_parameter(value):
    if not wait_until((in8(0142H) & 01H) == 0): return timeout
    out8(0146H, value)
    return success

read_result_byte():
    if not wait_until((in8(0142H) & 02H) != 0): return timeout
    return in8(0146H)
```

## コマンドの詳細

### 10H：SYNC — CRT走査の設定

【汎用】【VA資料】14バイトを送る。`p[0]` を最初のパラメータとする。

| バイト | bit | フィールド | 内容 |
| ---: | --- | --- | --- |
| 0 | 7:6 | RM | ラスタモード |
| 0 | 5 | EL | ライトペン割込み許可（汎用） |
| 0 | 4 | EV | 垂直帰線割込み許可（汎用） |
| 0 | 3 | VM | 静止画メモリアクセス方式 |
| 0 | 2 | — | 予約、0 |
| 0 | 1 | DPM | デュアルポート選択 |
| 0 | 0 | ILM | インターリーブ選択 |
| 1 | 7 | — | 予約、0 |
| 1 | 6 | RF | リフレッシュ許可 |
| 1 | 5 | EC | 内部分周ドットクロック出力 |
| 1 | 4 | ES | 同期信号出力／外部同期選択 |
| 1 | 3 | RV | テキスト前景・背景の全体反転 |
| 1 | 2:0 | RS | ドットクロック分周・解像度指定 |
| 2 | 5:0 | LBL | 左blanking |
| 3 | 5:0 | LBR | 左border |
| 4 | 7:0 | HAD | 水平有効表示 |
| 5 | 5:0 | RBR | 右border |
| 6 | 5:0 | RBL | 右blanking |
| 7 | 5:0 | HS | 水平同期幅 |
| 8 | 5:0 | TBL | 上blanking |
| 9 | 5:0 | TBR | 上border |
| 10 | 7:0 | VAD下位 | 垂直有効表示の下位8ビット |
| 11 | 6 | VAD上位 | VADのbit 8 |
| 11 | 5:0 | BBR | 下border |
| 12 | 5:0 | BBL | 下blanking |
| 13 | 5:0 | VS | 垂直同期幅 |

`VAD = p[10] | ((p[11] & 40H) << 2)`。
上位ビットは `p[11]` のbit 6であり、単純な16ビットlittle-endianではない。
水平の基本単位は4ドット。汎用の有効幅は `(HAD + 1) * 4`。

| RM | 汎用での分類 | VAでの代表的な解釈 |
| --- | --- | --- |
| `00b` | Noninterlace | 24.8 kHz・400ライン |
| `01b` | Interlace | 15 kHz・400ライン相当 |
| `10b` | Vertical magnification | 24.8 kHzで200ラインを縦拡大 |
| `11b` | Normal | 15 kHz・200ライン。24.8 kHzのスプライト解釈にも使う |

RMだけで完成した画面モードが決まるわけではない。外部クロック、同期、
GVRAM側の設定、スプライトのライン解釈を合わせて考える。
汎用RSの内部クロック例は `000b`=/4、`001b`=/3、`010b`=/2、
`011b`=/1.5、`100b`=/1。VAの既知ベクタはRS=`111b`で外部クロックを使う。
内部クロック例の256ドット表示を、そのままVAのGVRAM表示モードとは呼ばない。

【実装】14バイトを保存し、テキスト縦拡大と有効ライン数を更新する。
完了するとテキスト表示を停止する。再開には `DSPON` が必要であり、
`SYNC` 自体はスプライト表示フラグを停止しない。この区別はM104で修正済み。
割込み、メモリアクセス方式、リフレッシュを含む全フィールドの完全再現ではない。

#### 既知の標準ベクタ

【VA資料】既存解析が整理した設定値。各行は14バイトである。
「200→400」は200ラインのテキストを縦拡大する走査で、VAD自体は400になる。

| 表示 | 走査 | 解釈 | パラメータ列 |
| --- | --- | --- | --- |
| 200 | 15.98 kHz | 200ライン | `C1 57 1C 00 9F 00 10 0F 25 00 C8 00 0F 08` |
| 200 | 15.73 kHz | 200ライン | `C1 47 1C 00 9F 00 12 11 24 00 C8 00 17 04` |
| 200→400 | 24.8 kHz | 縦拡大 | `81 57 10 00 9F 00 10 0F 19 00 90 40 07 08` |
| 204 | 15.98 kHz | 204ライン | `C1 57 1C 00 9F 00 10 0F 23 00 CC 00 0D 08` |
| 204 | 15.73 kHz | 204ライン | `C1 47 1C 00 9F 00 12 11 22 00 CC 00 15 04` |
| 204→408 | 24.8 kHz | 縦拡大 | `81 57 10 00 9F 00 10 0F 19 00 98 40 07 08` |
| 400相当 | 15.73 kHz | インターレース、200ラインのスプライトデータ | `41 47 1C 00 9F 00 12 11 24 00 C8 00 17 04` |
| 400 | 24.8 kHz | 200ラインのスプライトデータ | `01 57 10 00 9F 00 10 0F 19 00 90 40 07 08` |
| 400 | 24.8 kHz | 400ラインのスプライトデータ | `C1 57 10 00 9F 00 10 0F 19 00 90 40 07 08` |
| 408相当 | 15.73 kHz | インターレース、200ラインのスプライトデータ | `41 47 1C 00 9F 00 12 11 22 00 CC 00 15 04` |
| 408 | 24.8 kHz | 200ラインのスプライトデータ | `01 57 10 00 9F 00 10 0F 19 00 98 40 07 08` |
| 408 | 24.8 kHz | 400ラインのスプライトデータ | `C1 57 10 00 9F 00 10 0F 19 00 98 40 07 08` |

走査変更は `SYNC` の送信だけで済まない。
[表示モード制御](../modernization/pc88va-video-modes.md)および
[走査変更手順](../modernization/more-screen-resolutions.md#32-解像度変更時の共通コマンド列)
を参照し、`0100H` 側の表示禁止・同期停止・リセット・再開手順も守る。
未知の値を実機CRTへ試すことは勧めない。

#### タイミング上の注意

【実装】水平総ドット数は次の式で計算している。

```text
4 * ((LBL + 1) + LBR + (HAD + 1) + RBR + (RBL + 1) + (HS + 1))
```

汎用データブックではLBRとRBRにも `+1` があり、同じ式ではない。
vaegは実機合わせのコメントに基づくVA側の計算を採用している。
垂直総ライン数は `TBL + TBR + VAD + BBR + BBL + VS`。

【既存実機記録】M104/M105では標準表以外の走査も調べている。
例えば15.98 kHzのVAD=224/240、24.8 kHzでの長いフレームやVS=1の観察がある。
これは全機種・全モニタの保証ではない。vaegはVSが0のときだけ1へ引き上げ、
汎用資料の最小値4へ一律に引き上げない。
[測定条件と結果](../modernization/pc88va-video-modes.md#12-measured-non-native-timings)を参照。

### 12H：DSPON — テキスト表示開始

| バイト | 内容 |
| ---: | --- |
| 0 | 画面制御テーブルの256バイトページ番号・下位 |
| 1 | 上位ページ情報（汎用） |
| 2 | 背景色（汎用では下位4ビット） |

【VA資料】初代VAの慣用位置はTVRAMオフセット `7F00H`。
その場合は `7F 00 00` を送る。残り2バイトが通常0でも、送信は省略しない。
4個の分割画面記述子をTVRAM上に準備してから開始する。

【実装】`texttable = p[0] << 8` としてテキスト表示をONにする。
`p[1]` と `p[2]` は受信するが、テーブル上位・背景色には反映しない。
スプライト開始は別の `SPRON`。

### 13H：DSPOFF — TSP表示停止

パラメータなし。テキストとスプライトの両表示を停止する。
同期・帰線の生成やGVRAM画面の表示停止とは別である。
スプライトを残してテキストだけ隠す場合はVA側の `0148H.TD` を使う。

### 14H：DSPDEF — テキスト表示形式

| バイト | フィールド | 内容 |
| ---: | --- | --- |
| 0 | ATROFF下位 | 属性領域までのオフセットbit 7:0 |
| 1 | ATROFF中位 | bit 15:8 |
| 2 | PITCH / ATROFF上位 | bit 6:4=PITCH、bit 2:0=ATROFF bit 18:16 |
| 3 | MRA | bit 4:0。1文字のラスタ数−1 |
| 4 | HRA | bit 4:0。ホリゾンタルライン位置 |
| 5 | BR | bit 7:3。点滅速度 |

【汎用】ATROFFは符号付き19ビットのバイト差。
PITCHは0で無効、1–7で1–7バイト進み。VAネイティブ文字は通常2バイト。
MRA=`07H/0FH/1FH` は8/16/32ラスタ、`00H–06H` は文字表示無効。
HRAは0が最初のラスタ、underlineは最後のラスタに出る。

【汎用】BR=1–31の属性点滅は明期 `BR*24` fields、暗期 `BR*8` fields。
カーソルは両期とも `BR*8` fields。BR=0は32として扱う。
fieldは常にフレームと同じとは限らず、インターレース時は区別する。

【実装】ATROFFは下位16ビットだけを保存し、PITCHは使わない。
文字高は `p[3]+1`、HRAは `p[4]` をそのまま保存するため、汎用の予約ビットmaskや
文字表示無効の解釈まで一致するとはいえない。BRは `p[5]>>3` を点滅カウンタへ
入れるが、コードには周期の解釈に関する未解決コメントがある。

### 15H：CURDEF — カーソル定義

| bit | フィールド | 内容 |
| --- | --- | --- |
| 7:3 | CURN | カーソルに使うスプライト番号0–31 |
| 2 | — | 予約 |
| 1 | CE | 1でカーソル表示許可 |
| 0 | BE | 1でカーソル点滅許可 |

カーソルは独立した図形ではなく、選んだスプライトのパターンと座標を使う。
CEと記述子の通常表示SWは別の状態。CEで表示するカーソルはSWが0でも対象になる。
`SPRON` と有効な記述子・パターンが必要で、`SPROFF` はカーソルも止める。
BIOSが31番をテキストカーソルに使うのはソフトウェアの予約であり、
CURDEFが31番しか選べないという意味ではない。

### 16H：ACTSCR / 1EH：CURS — 対象画面とカーソル座標

ACTSCRは1バイトで、bit 6:5に分割画面番号0–3を指定する。
値は `画面番号 * 20H`。後続のCURSで使う仮想座標系を選ぶ。

CURSは4バイト：`Y下位、Y上位、X下位、X上位`。
座標は文字行・文字列であって画面ドット数をそのまま送るものではない。
【汎用】仮想画面の右／下端でclampし、DPTR0も対応位置に更新する。

【実装】選択画面のRXP/RYPを原点とし、`X*8+RXP`、
`Y*lineheight+RYP` をカーソル用スプライトへ書く。
スプライト縦拡大時はYを半分にする。仮想範囲clampとDPTR0更新は未再現。
初代VAのV1/V2カーソル経路で使われる。VA2側は記述子を直接書く経路もある。

### 81H：SPROV — スプライト状態読出し

【VA資料】【汎用】結果の1バイトは次の形式。

| bit | フィールド | 内容 |
| --- | --- | --- |
| 7 | — | 予約 |
| 6 | SO | スプライトオーバー検出 |
| 5 | C/CD | 衝突検出 |
| 4:0 | OVS | 最初にオーバーとなったスプライト番号 |

SCをクリアする読出し操作。VA資料にはVRTC開始から160 μs以内に取得するという
条件がある。詳細情報のラッチ寿命や全機種でのタイミングは追加確認が必要。
【実装】vaegはこのコマンドと結果読出しを実装していない。

### 82H：SPRON / 83H：SPROFF

SPRONは3バイト。

| バイト | 内容 |
| ---: | --- |
| 0 | スプライトテーブルの256バイトページ番号・下位 |
| 1 | 上位ページ情報（汎用） |
| 2 | bit 7:3=HSPN、bit 2=ESP、bit 1=MG、bit 0=GR |

- HSPN：1走査線あたりの個数しきい値。`HSPN+1` 個を超えるとオーバー。
- ESP：【汎用】スプライト割込み許可。VAでの割込み配線は未確定。
- MG：全スプライトの縦2倍拡大。
- GR：衝突を異なる色グループ間だけで判定する。

【実装】`sprtable=p[0]<<8`、`hspn=p[2]>>3`、MG/GRを保存して表示ON。
上位アドレスとESPは反映しない。HSPN/GRを保存することは、オーバー・衝突判定が
完成していることを意味しない。

SPROFFはパラメータなし。テキスト状態は変えずスプライトとカーソルを止める。

### 84H：SPRWR（vaeg名SPRDEF） / 85H：SPRSW

【汎用】SPRWRはスプライト番号／属性バイトの選択に続き、記述子データを連続で
受け取り、次の記述子へ進む。vaegでは `SPRDEF` という名前を使う。

【実装】最初のパラメータをテーブル内の**バイトオフセット**として保存する。
続く各バイトを `textmem + sprtable + offset` へ書き、8ビットoffsetを増やす。
`FFH` の次は `00H` に戻る。新しいコマンドが来るまで書込みモードが続く。
この経路は固定長受信とは異なり、書込み終了時に自動でBUSYをクリアしない。
通常の05H待ちだけで終了コマンドを送る例は示さない。汎用の選択子・終了条件と
VAの厳密な関係は未確定である。

SPRSWは1バイト。bit 7:3で番号を選び、bit 1を記述子SWへ書く。
残りの座標・サイズ・パターンは変えない。CEとは別なので、カーソルとして
有効なスプライトは通常SWを0にしただけでは隠れない場合がある。

### 88H：EXIT — 受信・転送の終了

【汎用】【VA資料】途中のパラメータ受信や連続メモリ操作を終了し、
エラー状態から復帰する。μPD3301互換属性展開も止める。
受信完了済みの全コマンドを必ず取り消す、という意味ではない。

【実装】パラメータ処理をNOPへ切り替え、`emul=0`、BUSY=0にする。
ER生成・結果FIFO・汎用DMAの全状態を回復するモデルは存在しない。

### 8CH：EMUL — μPD3301互換属性展開

【VA資料】V1/V2用の動的な文字属性展開であり、汎用μPD72022の通常コマンド一覧には
ない。受信した行を一度だけ書き換えて終わる操作とは区別する。

【実装】4バイトを次の式で解釈する。

| バイト | vaegでの意味 |
| ---: | --- |
| 0 | 分割画面番号：`(p[0]>>5)&3` |
| 1 | 1行の文字数−2 |
| 2 | 1行の属性対数−1 |
| 3 | 行数−1 |

VA2 ROM経路で観察された設定として、ソースに次の例が記されている。

- `00 4E 13 18`：画面0、80文字、20属性対、25行。
- `00 4E 13 13`：画面0、80文字、20属性対、20行。

展開状態は `tsp.emul` に保存され、テキスト描画側が参照する。
ステータスEMENは生成しないので、vaegでEMENを待つと仕様どおりに動かない。
【未確定】異常な行データ、属性対数の超過、分割境界での初期化条件。
既存資料の「別コマンドで終了」と現在の実装は一律に同じではなく、vaegでは
`EXIT` と `SYNC` がemulをクリアするが、全コマンドがクリアするわけではない。

## ROM使用に基づくメモリ転送経路

`8EH/8FH/97H` はVA資料の通常のコマンド一覧だけでは説明できない。
【実装・既存ROM解析】VA2のV1/V2経路ではCPUからTVRAMへ直接到達できないときに、
これらで分割画面テーブルのフィールドを書いている。現在のソースの意味は以下。

| コード | vaeg内部名 | 入力 | 現在の動作 |
| --- | --- | --- | --- |
| `8EH` | TVADDR | 3バイト | TVRAMの18ビット**バイトアドレス**を下位から設定。3バイト目は `&03H` |
| `8FH` | TV8F | 3バイト | 受信してBUSYをクリアするだけ。用途未確定 |
| `97H` | TVWRITE | 連続バイト | 設定アドレスから書き、1バイトずつ加算。18ビットでwrap |

`97H` の連続入力は次のコマンドまで続き、ソースではBUSYをクリアして受信する。
これを汎用DPLD/WDATの完全実装と呼ばない。特に汎用資料の19ビットアドレス、
word転送、MASK、DPTR1と、現在の18ビットバイトストリームは区別する。
VA2で使われた事実だけから初代VA・VA3の全転送条件を断定しない。

## 汎用μPD72022の追加コマンド

以下は汎用の参考一覧。通常のVA用コマンド一覧への掲載、VAでの利用可能性、
現在のvaeg対応は別問題である。直接TVRAMをCPUから読む／書く経路の存在も、
これらのTSPコマンドが動く証拠にはならない。

| コード | 名称 | 機能・注意 | 現在のvaeg |
| --- | --- | --- | --- |
| `1AH` | LPNR | ライトペンY、Xを4バイトで取得。VAではライトペン使用不可 | 未実装 |
| `80H` | SPRRD | スプライト記述子を連続読出し | 未実装 |
| `89H` | MASK | 16ビットのメモリ書込みmaskを設定 | 未実装 |
| `8AH` | DPRD | DPTR0を3バイトで取得 | 未実装 |
| `8EH/8FH` | DPLD | 19ビットDPTR0/DPTR1設定。DPTR1は符号付き増分にも使う | 上述のVA2向け限定経路のみ |
| `90H–93H` | RDAT | ホスト経由で表示メモリ連続読出し | 未実装 |
| `94H–97H` | WDAT | mask付きの連続書込み | `97H` の限定バイト転送のみ |
| `99H–9BH` | BLKTOT | 表示メモリ→ホストのDMA転送 | 未実装 |
| `9DH–9FH` | BLKTIN | ホスト→表示メモリのDMA転送 | 未実装 |

【汎用】転送のMODは、`00b`=ポインタ不変、`01b`=ATROFF加算、
`10b`=PITCH加算、`11b`=符号付きDPTR1加算。DMAのMOD=00は無効。
MASKは `new=(old & ~mask)|(input & mask)` というbit単位の更新。
全転送のバイト順、VAのアドレス変換、DMA終了・割込み条件は別途確認が必要。

## TVRAM・テーブルとの関係

### アドレス単位と機種差

【VA資料】初代VAは64 KiB、VA2/VA3は256 KiBのTVRAMを持つ。
CPU側のシステムメモリバンクでTVRAMを選ぶ操作はTSPコマンドとは別。
初代VAのCPU可視窓は `A0000H–AFFFFH`。

| 対象 | 単位 |
| --- | --- |
| CPUのTVRAMアクセス | バイト |
| DSPON/SPRONのテーブル先頭 | 256バイトのページ番号 |
| 画面テーブルのVSA/RSA | TVRAM基準のバイトオフセット |
| DSPDEFのATROFF | 属性までのバイト差 |
| 文字・属性・スプライトパターンのTSP fetch / SPDA | TSPワードアドレス |

初代VAのパターン／文字fetchでは、CPU側の2つの32 KiB領域に対応するTSPワード
アドレスが連続ではない。

| TSPワードアドレス | CPUのTVRAM内バイト位置 | CPUアドレス |
| --- | --- | --- |
| `0000H–3FFFH` | `0000H–7FFFH` | `A0000H–A7FFFH` |
| `8000H–BFFFH` | `8000H–FFFFH` | `A8000H–AFFFFH` |

例えばTSP `0001H` はCPUオフセット `0002H`、TSP `8000H` はCPUオフセット
`8000H`。単純に全ワードアドレスを2倍してはいけない。
残りのTSPワード範囲の初代VAでの挙動、VA2/VA3の全アドレスdecodeは未確定。
汎用チップの最大512 KiBという値は、VAの搭載TVRAM容量ではない。

### 初代VAの慣用配置

| TVRAM内オフセット | CPUアドレス | 用途 |
| --- | --- | --- |
| `7E00H–7EFFH` | `A7E00H–A7EFFH` | 32個×8バイトのスプライト記述子 |
| `7F00H–7F7FH` | `A7F00H–A7F7FH` | 4個×32バイトの画面記述子 |
| `7F80H–7FFFH` | `A7F80H–A7FFFH` | 制御ページ内の予約部分 |

これはBIOS等の慣用位置。コマンドでテーブルページを選択できるため、
ハードウェアの絶対固定アドレスではない。VA2/VA3のBIOS配置へ無条件に流用しない。

### 画面記述子（1個32バイト）

【VA資料】マルチバイト値はlittle-endian。予約フィールド・予約bitは0。

| オフセット | フィールド | 内容 |
| --- | --- | --- |
| `00H` | VSA | 仮想画面の開始バイト位置、19ビット |
| `04H` | VH | 仮想画面の高さ、文字行単位、11ビット |
| `08H` | VW | 仮想画面の行幅、バイト単位、10ビット |
| `0AH` | BG / FG / MODE | bit 15:12=背景、11:8=前景、4:0=属性モード |
| `0CH` | RASTER_OFFSET | bit 12:8=ラスタスクロール量 |
| `10H` | RSA | 表示するソース開始バイト位置、19ビット |
| `14H` | RH | 表示領域の高さ、ラスタ単位、9ビット |
| `16H` | RW | 表示領域の幅、ドット単位、10ビット |
| `18H` | RYP | 表示領域のY位置、9ビット |
| `1AH` | RXP | 表示領域のX位置、10ビット |

未使用wordは `06H/0EH/1CH/1EH`。VSA/RSAの上位3ビットは次wordの下位bitに入る。
画面分割・スクロールはTVRAM上のこのテーブルとTSP設定の組合せで決まる。
仮想範囲外の出力、MODE=3の状態持越し、`RW/8+2` セルfetchのclippingには
未解決点があり、現在の描画が全仕様を満たすとはいえない。

属性MODE=0–5の概要は、0=前景／背景各4bit、1=前景＋形状、2=形状、
3=色／形状の状態付き切替え、4=点滅＋色、5=4に特定色の水平線を加えた形式。
[全ビットの説明](../modernization/upd72022-tsp.md#124-attribute-modes-0-through-5)を参照。
【既存実機記録】MODE=6–31も試されているが、利用可能な表示形式として確立して
いない。再現性のある模様が出たことを、新しいグラフィックスモードの保証にしない。

### スプライト記述子（1個8バイト）

| オフセット | bit | フィールド | 内容 |
| --- | --- | --- | --- |
| `00H` word | 15:10 | YSIZE | 高さ=`4*(YSIZE+1)` ドット |
| `00H` word | 9 | SW | 通常表示許可 |
| `00H` word | 8:0 | YP | Y座標、9ビット |
| `02H` word | 15:11 | XSIZE | 1行のパターン容量=`4*(XSIZE+1)` バイト |
| `02H` word | 10 | MD | 0=packed color、1=monochrome |
| `02H` word | 9:0 | XP | X座標、10ビット |
| `04H` word | 15:0 | SPDA | パターンのTSPワードアドレス |
| `06H` byte | 7:4 | FG | モノクロの前景色 |
| `06H` byte | 3 | BC | 0bitの出力：0=透明、1=色8 |

packed colorは4bpp、高nibbleが左のドット、低nibbleが右。色0は透明。
幅は `8*(XSIZE+1)` ドット。monochromeは1bpp、bit 7から左→右へ読む。
幅のフィールド計算は `32*(XSIZE+1)` だが、実用上の最大幅は資料間の食い違いが
あり、全1024ドット幅を実機保証しない。

32個のうち番号0が最優先。カーソル・マウスの番号予約はBIOSの運用規則。
座標はXが10ビット、Yが9ビットのmodular表現で、−1はそれぞれ1023/511。
初代VAのパターンはCPU `A8000H` の境界をまたがせない。
上端clipping、衝突グループ、走査線あたりの転送能力は単純な個数制限だけでは
説明できない。[スプライト詳細](../modernization/upd72022-tsp.md#13-sprite-engine)を参照。

## 関連するVA側ポート

ここはTSPコマンドとの境界を示すための要約。個々のポートの完全な仕様書ではない。

### 0148H：テキスト制御

【VA資料】主なフィールドは以下。

| bit | 名称 | 内容 |
| --- | --- | --- |
| 7 | TD | 1でテキスト表示禁止。スプライト表示とは別 |
| 6:4 | VALT | TVRAMアクセス制限。0は無制限、非0は値×4アクセスと記載 |
| 3 | ATM | 0=V3 native、1=V1/V2互換 |
| 2 | ANKM | 0=8×16 ANK、1=8×8 ANK |
| 1 | TVWM | 0=byte構成、1=word構成 |
| 0 | 機種依存 | 初代VA資料では1。全機種で固定と断定しない |

VALTのアクセスを数える期間、bit 0の機種差は未確定。
【実装】`io/videova.c` の書込み処理はbit 0を1にし、0指定に対し
256 KiB TVRAM modeに関する未対応警告を出す。TVRAMの搭載容量、CPUの可視窓、
この制御bitの意味は分けて考える。

### 表示合成・文字幅

| ポート | 関係 |
| --- | --- |
| `0030H` bit 0 | 40/80桁選択。40桁はVA側の水平拡大で、TSPの文字DWIDとは別 |
| `0100H` | グラフィックス垂直走査、同期・表示制御 |
| `0102H` | G0/G1の640/320ドットとピクセル形式。TSPのHADとは別 |
| `0106H` | パレット系の表示優先順位 |
| `0108H` | direct-color側の優先順位 |
| `0111H` 上位nibble | TSP出力色のsprite/textクラス境界N |
| `012EH` | TSP出力色ごとの透明指定、16ビット |
| `0200H–027FH` | GVRAMのフレームバッファ記述子。TVRAM画面テーブルではない |

TSPは元来1本の4ビット色出力で、内部では不透明なスプライトがテキストより優先。
VA側は色1–Nをspriteクラス、N+1–15をtextクラスに分け、G0/G1との合成順を
選べる。色0は透明。クラス名は描画元の種類そのものではなく**出力色による分類**。
これをスプライト自身の番号優先順位と混同しない。

## 初期化・変更時の確認事項

1. モニタ／同期方式に合う、既知の完全なSYNCベクタを選ぶ。
2. 走査を変更するなら、VA側の同期・グラフィックス回路の停止／再開手順を守る。
3. SYNC、DSPDEFを必要なバイト数だけ送る。
4. CPUのTVRAMバンクを正しく選び、分割画面テーブルと文字・属性を準備する。
5. 必要ならスプライトテーブル・パターン、CURDEFを準備する。
6. SPRON、DSPONで必要な表示を開始する。
7. 0148H、文字幅、パレット、色境界、透明、優先順位を整合させる。
8. すべてのpollにtimeoutを設け、未実装コマンドの結果待ちを無期限にしない。

これは機能間の依存関係の整理であり、PC-EngineやBIOSの管理状態を保存・復元する
完成したプログラムではない。直接I/Oを触るソフトは終了時の画面・バンク・
パレット復元も必要になる。

## 未確定事項・検証範囲

- `0143H` の実機機能。vaegの `FFH` スタブから「予約」「存在しない」と断定しない。
- IBF/BUSY/OBFの実機での時間関係、FIFO容量、ER発生・解除条件。
- SPRWR/SPRDEFの選択子、BUSYの寿命、終了／回復手順。
- `8EH/8FH/97H` の全意味と機種差、汎用DPTR/MASKとの関係。
- SC/SPROV、HSPN、衝突グループ、割込み配線とラッチ寿命。
- TVRAMのTSP側アドレスdecode、VA2/VA3の上位アドレス。
- MODE=3の状態境界、未文書化MODEのfetch、仮想範囲外の出力。
- VALT、0148H bit 0、文字・カーソルの点滅周期。
- LBR/RBR、外部同期、インターレースを含む全走査条件。
