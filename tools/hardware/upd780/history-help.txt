M140 FDC HISTORY PROBES - supported VA/VA2 monitor only

Use a WRITABLE COPY, with no other disk work during FDC takeover.
Keep the running VA2 measurement undisturbed; use this disk AFTER it ends.

First FDCHIST, then FDCFLAG, waiting for A> after EACH command.
Results are FDCHIST.TXT and FDCFLAG.TXT. Both have 512 Q records.
Wait for M139_FDC_RAM_RESTORED AND A> before any disk operation.
M139 is the compatible v1 transport identifier, not the milestone name.
Never rerun over an existing log: it is refused, not overwritten.
Return the result disk with model, V1/V2, H/S and run order recorded.
Do not change settings while a diagnostic is running.

Q h op requested-AF before-AF after-AF
h: 0=no extra instruction, 1=NOP, 2=LD A,A, 3=OR A,
   4=AND A, 5=CP A, 6=SCF, 7=CCF
op: S=SCF, C=CCF
Every span begins DI; XOR A; PUSH BC; POP AF.
A separate identical-prefix control captures before-AF. No snapshot,
CALL, monitor/output or dispatch interrupts predecessor/IUT adjacency.
This controls instruction history, NOT an independently verified Q value.
FDCHIST covers X/Y and carry combinations; FDCFLAG covers broad S/Z/PV/N/H.
No physical MHz is inferred. No NEC-specific flag correction is assumed.

TIMEOUT/RECOVERY_FAILED/TIMER_WRAP/LOG_CAPACITY: no more disk work; RESET.
Full FDCZEX need not be repeated unchanged just to collect these new cases.
Keep existing VA/VA2 full-ZEX and FDCPRB logs on their original result disks.
