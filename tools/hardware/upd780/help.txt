M139 FDC uPD780 diagnostic controller, CP/M 2.2

Run these programs on the VA/VA2 monitor family documented in the source.
Do not use an unknown subsystem ROM revision. Main CPU CP/M is only the
loader/recorder: the diagnostic instructions execute on the FDC CPU.
Use a COPY of the disk, leave it inserted, and keep normal peripherals idle.

FDCONE  : NEG-only smoke test. NOT full ZEXALL. Try this first.
FDCPRB  : 256 AF input pairs, readback and BIT/AND/SCF/CCF observations;
          separate RAM-resident timing loops, two repetitions, N=1/4/16.
FDCZEX  : All 67 relocated ZEXALL groups. This can take HOURS.

Wait for M139_FDC_RAM_RESTORED and the A> prompt.
Logs are FDCONE.TXT, FDCPRB.TXT and FDCZEX.TXT. Disk writes occur ONLY
AFTER diagnostic completion and byte-verified restoration of 4000-7EFF.
The existing output filename is refused: rename a previous log first.
Main CPU code uses a private stack, restores default DMA and returns to CP/M.

F records: requested AF, actual readback AF, BIT 0,A, AND 55h, SCF, CCF.
Each AF field has four hex digits, concatenated in that order.
E=XXXX counts BOTH edges of Port 40h bit 5 (VRTC). It is not MHz or us.
No reference frequency is guessed. Calibration requires an independently
approved VRTC frequency, its identity and the host-side results.py tool.
Timed loops contain no protocol or disk I/O. Branch baseline and empty
notification measurements separate loop/control and fixed overhead.

ZEX rows print STOCK= and CRC=. Relocation and the LD r,n scratch-address
change mean stock CRC mismatches ALONE are NOT evidence of NEC differences.
Compare the identical mapped image on host and FDC, then minimize any delta.
FDCZEX/FDCONE derive from GPL-2.0-or-later ZEX code; this build selects GPLv3.
See ZEXLIC.TXT and generated sources beside this private image.
Independent tools/controllers are BSD-2-Clause.
This image also contains private input system files: DO NOT REDISTRIBUTE.

During takeover, ordinary FDC disk service is suspended and motors are off.
Do not remove the disk, invoke another disk utility, or interrupt the probe.
To abort or on M139_FDC_TIMEOUT/RECOVERY_FAILED/TIMER_WRAP/LOG_CAPACITY,
RESET THE MACHINE. Do not attempt to save through an unknown FDC state.
The controller intentionally halts rather than issue unsafe disk writes.
A completed log is an observation, NOT physical conformance acceptance.
